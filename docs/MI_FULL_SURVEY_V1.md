# AS/400 CISC MI object survey v1 — methodology and results

This is a high-level survey of **268 IBM-documented MI types**, not a
claim that all of their binary structures are decoded or that each
type existed in V2R3. The underlying type names are from later
IBM tables (102 external, 166 internal).

## Evidence used

The project combines:
- audited decoder maturity for 28 object types, with 240 still
  explicitly marked catalog-only;
- historical manuals: 18 available PDF text layers scanned,
  764 exact IBM object-type tokens across 86 type names, and
  selected, independently reviewed manual pages for 19 types;
- two read-only HDA image scans of every physical sector, requiring
  a plausible CISC primary EPA signature, nonzero page count, and
  syntactically valid EBCDIC object name;
- documented or observed type relationships in the decoder registry;
- an editable project-value and estimated-feasibility scoring model.

Original image contents, recovered names and manual page text are
NOT included in the GitHub results. A physical primary candidate
is not necessarily context-confirmed, active, or unique.

## Results from both images

| Quantity | Mark V2R3 | Pete B10 |
|---|---:|---:|
| 520-byte physical sectors | 1,931,265 | 616,392 |
| Primary signature candidates | 20,271 | 7,570 |
| Distinct raw MI codes | 104 | 64 |

Across both images, **109 raw codes** have at least one physical
candidate. **106 of the 268 catalog types** have signature matches
on one/both disks; the other **162 have no signature match under the
chosen heuristic**, NOT proof of absence.

Three observed codes are absent from the modern IBM catalog:
- 0E/00: Pete 4 candidates, Mark 0;
- 19/C4: Pete 1 candidate, Mark 0;
- 19/ED: Mark 27 candidates, Pete 12.

No guessed names have been assigned.

The previous four-family scan knew only three *PGM segment tag
variants. The broader scan also finds *PGM candidate tags 82,
83 and 91. That increases Mark's candidate count from 4,286
to **4,346**, and Pete's from 3,081 to **3,102**. These extra
matches are additional *candidates*, not verified active programs.

## Reproducible research priority scoring

| Factor | Weight | Nature |
|---|---:|---|
| Project value | 30% | Curated archiving/5250 usefulness estimate |
| Shared unlocks | 25% | Audited logical links plus curated potential |
| Evidence | 20% | Reviewed source pages, tentative lexical matches, image candidates, audited code |
| Feasibility | 15% | Estimated prospective difficulty |
| Image coverage | 10% | Capped abundance of physical primary candidates |

Every factor is assigned 0–5. Score is the weighted sum /5,
giving 0–100. These **rankings are planning hypotheses**, not
IBM assertions or validated development time estimates.

The scoring model is editable in
research/mi_survey_scoring.json; the full per-type outputs are
generated by tools/mi_survey_priorities.py and published in
docs/MI_SURVEY_PRIORITIES.md. Never interpret unknown as zero
probability; never treat lexical hits as decoded field offsets.

## Proposed sequencing from the high-level sweep

1. Common EPA/virtual-extent, *LIB context and *FILE/*MEM
   recovery; strengthen *QDDS/*QDDSI/*FMT/*QDIDX foundations.
2. Interactive command/5250 information: link *CMD (separate
   draft PR #15) to *MSGF message descriptions and *MENU options
   using corroborated on-disk structures, not strings alone.
3. Recover system topology from *DEVD/*CTLD/*LIND and *MODD
   with cross-validated historic configuration references.
4. Retain *PGM/MI/ODT disassembly as a parallel long-term
   research track: high-value, low short-term feasibility.
5. Continue DLO, security-sensitive profile, queue/journal,
   and internal infrastructure work as specimen evidence permits.
6. Investigate raw 0E/00, 19/C4, 19/ED codes independently.

Within each stream: source terminology and release-specific
document pages -> two-image sample/candidate inventory ->
pointer/field hypotheses -> synthetic bounds/corruption tests ->
read-only display -> human validation -> decoder maturity update.

## Distinct provenance states to preserve

- Observed as a physical-primary *candidate*;
- not observed with this signature (not the same as absent);
- confirmed in a current library context traversal;
- documented for a specific OS/400 release;
- decoded binary attribute validated against independent evidence.

The first 28 reviewed types have a head start; no claim is made that
all 268 types have a human-reviewed manual chapter. Service manuals
and CISC System Builder PDFs have few exact star-prefixed type names,
but may still be rich in relevant LIC/MI storage terminology.

## Reproduction

From the repository checkout:

    python3 tools/mi_full_primary_survey.py /path/to/marks.hda.zip
    python3 tools/mi_full_primary_survey.py /path/to/petes.hda.zip
    python3 tools/mi_survey_priorities.py --format summary
    python3 tools/mi_survey_priorities.py --format json
    python3 tools/mi_survey_priorities.py --check-report

All on-image scans are read-only and export aggregate data only.
The ranking tool works from committed metadata alone, without
the original archive files. Run unit and CI tests after any
catalog, evidence or weighting change.
